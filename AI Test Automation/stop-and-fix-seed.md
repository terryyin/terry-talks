**Goal:** Give Terry a finished, engaging revision of his short film for people
working in large legacy software organizations where tickets arrive faster than
the team can close them. Make the value of automated tests clear before revealing
their upkeep, and make stopping the accumulation of complexity an emotionally
convincing turning point toward repair and regained control.

#### Scope

This is a new authorized revision of the finished film. Terry's continuing
delegation includes producing the improved movie and its consistent article,
then committing and pushing the finished work. This preparation does not itself
admit the story, implement the film, or publish changes.

Keep the opening order: "Ask AI to write more tests?" then "You probably don't
want to do that." Establish the overloaded legacy context, the diagnosis "not
enough automated tests," and "you're probably right." Then justify automated
tests: they express the **purpose** of the production code's dynamic behavior
and provide **proof** that the purpose is fulfilled in the behavior checked.
The article clarifies the limits of that proof: encoded expectations and observed
examples, not a universal guarantee that no bugs remain.

Only after those benefits, reveal that an automated test is first and foremost
more code. Reliable test automation requires high-level software engineering and
must protect the original genuine intent. AI can pile on code and complexity
before that code provides protection. Do not retain the separate targeted-test
beat; Terry explicitly removed it from the film's flow.

Make **STOP AND FIX** a large, unmistakable turning point. Ground it in
[Terry's Stop & Fix claim](../TPS%20and%20AI/claims/19-stop-and-fix.md): stop
compounding the problem, contain it, and make repair the current work. Get the
system back under control before introducing new complexity. This means a change
of work, not a claim that every useful action or carefully justified repair test
must stop.

State the alternative directly: AI performs hands-on testing. First establish
an isolated, repeatable test environment that is easy to set up. Show AI manual
checks, then have it perform similar hands-on tests: confirm fixes, explore for
new bugs, and check that known behavior still works. Show the emotional
compromise: this does not eliminate repeated checking as ordinary automated
tests can, but at least it does not pile maintained test code onto a system
already in panic. The article retains the costs of environments, checking,
triage and human judgment; do not promise zero cost or guaranteed AI findings.

After control returns, turn useful checks into ordinary repeatable test code
that needs no AI judgment to run. For new features in a manageable development
cycle, express and protect the developer's intent in tests first and let them
drive development. Continue simplifying and optimizing the suite, deleting
redundant tests and moving suitable local checks to units while keeping essential
end-to-end protection. End with spare AI used to simplify and fix, and a short,
memorable closing line consistent with that idea.

Make voice and presentation more dramatic through contrast, pauses, character
reaction and decisive physical action. Keep the recognizable warm paper/ink
Story Impact family, simple visual focus, readable captions, fixed-length limbs,
reachable gestures, truthful synthetic Cedar credit and original sound. Aim for
roughly 75–80 seconds if the expanded argument needs it, staying within the
existing 85-second production ceiling. Preserve natural speech and emotional
space; do not force the old runtime by rushing or stretching audio.

The [article](ai-and-test-automation.md) remains the canonical consistent
argument. The original [transcript](source-transcript.md) stays unchanged.
Preserve earlier exported revisions for comparison. Shared redesign of other
films, unrelated main-checkout changes and posting to LinkedIn are outside this
revision.

#### Key examples

- A viewer hears the tempting automated-test diagnosis and its valid benefits
  before seeing a new code pile compete with a queue the team already cannot
  clear. PURPOSE and PROOF are intelligible before the upkeep objection.
- The code-generating momentum visibly stops at a prominent STOP AND FIX beat.
  The engineer changes attention from accumulating code to understanding and
  repairing the existing system, with a corresponding decisive narration pause.
- In a resettable isolated environment, AI follows demonstrated checking methods
  while also exploring similar behavior. A fix is confirmed, a variation can
  reveal another bug, and a known behavior is checked again; this is not merely
  the same click replayed or a claim of perfect coverage.
- The audience sees why this interim hands-on work is a compromise that avoids
  adding maintained test code to the panic. A later learned check becomes code
  that runs without AI; a new feature's intent is tested before feature code.
- Simplification removes redundant upkeep while useful end-to-end protection
  remains. The closing connects spare AI with fewer bugs and less complexity,
  rather than encouraging indiscriminate test or feature generation.
- Throughout revised gestures, rigid upper-arm and forearm lengths remain
  stable, hands reach their staged controls, and subtitles remain readable in
  the actual vertical export. More emotion does not add a busy diagram parade.
